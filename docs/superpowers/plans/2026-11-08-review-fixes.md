# AWG VPS Kit: исправления по ревью 2026-11-08

**Goal:** Исправить найденные при ревью ошибки и слабые места, не меняя формат `awg0.conf`, ключи, адреса и параметры обфускации существующих серверов.

**Исходные данные:** ревью всех скриптов (`install.sh`, `awg-client`, `update.sh`, `uninstall.sh`, `awg-watchdog`, `block-ping`), тестов, CI и документов на `c991994`. Действующие серверы не проверялись.

**Порядок:** фаза A (локальные изменения, проверяемые в контейнерных тестах CI) → фаза B (сеть/systemd, требует прогона на одноразовой ВМ по `docs/testing/reliability-vm.md`) → фаза C (решения и удобство).

## Отчёт ревью

### Ошибки
1. **`awg-client remove` удаляет соседний пир.** Удаление делит `awg0.conf` на абзацы (`RS=""`). Если между `[Peer]` нет пустой строки (ручная правка), два пира — один абзац, удаляются оба. Воспроизведено: удаление `alice` убрало и `bob`. Второй пир остаётся в runtime до рестарта и молча исчезает после.
2. **Асимметричный MTU без MSS clamping.** Клиент 1420, сервер `awg0` 1280. TCP MSS клиента ≈1380, ответы с DF не проходят через `awg0` → ICMP frag-needed; при фильтрации ICMP — PMTU black hole (зависают крупные загрузки).
3. **Watchdog молчит при `failed`.** Если рестарт не удался, юнит `failed`, `awg-watchdog` выходит на `is-active` и больше не пытается и не сигнализирует.

### Слабые места
4. Сборка из HEAD апстрима при каждом install/update (уже в TODO) — главный риск цепочки поставок.
5. `awg-quick@.service` создаётся heredoc'ом в `install.sh`, `update.sh` не может его мигрировать.
6. Падение `install.sh` в середине оставляет `awg0.conf`; повторный запуск отказывает, чистка вручную.
7. Нет проверки пересечения `--subnet` с существующими маршрутами.
8. После `systemctl restart nftables` watchdog восстанавливает NAT, но не правила ufw.
9. Дублирование кода (`take_lock` ×4, `rnd32`/H-генерация ×2, шаблон I1 ×2) — риск рассинхронизации.
10. Публичный IP только через `api.ipify.org`, нет запасного источника.
11. `awg0.conf.bak-*`, `protocol.bak-*` копятся бесконечно (содержат приватный ключ сервера, режим 600).

### Документация
- `TODO.md`: «client MTU follows the server (1280)» — неверно, по умолчанию 1420.
- `DECISIONS.md`: «Fixed MTU 1280» без упоминания клиентского 1420 и причины.
- `AGENTS.md`: у `awg-client` нет `protocol/mtu/version`, нет строки `block-ping`; `STATUS.md` не упоминает `mtu`.

## Фаза A — локально, контейнерные тесты

- [x] **A1. Построчное удаление пира** (п. 1). `awg-client remove`: awk по строкам, блок пира начинается с `[Peer]`/`[Interface]`; удалить ровно блок с `# <name>`, проверить, что число `[Peer]` уменьшилось ровно на 1, иначе `fail_txn`. Тест: конфиг без пустых строк между пирами, удаление одного сохраняет другого.
- [x] **A2. Документация** (раздел «Документация»): TODO, DECISIONS, AGENTS, STATUS.
- [x] **A3. Юнит `awg-quick@.service` в репозитории** (п. 5). Файл в корне, `install.sh` ставит его через `install -m 644`, `update.sh` обновляет его в `refresh_scripts` и в наборе `managed_files`, `uninstall.sh` без изменений (уже удаляет). Содержимое — байт в байт текущее, `.gitattributes` eol=lf, тест сравнивает установленный файл с репозиторием.
- [x] **A4. Проверка подсети** (п. 7). До установки: если `ip -4 route` уже содержит маршрут, пересекающий `$SUBNET.0/24` (кроме default), — отказ с подсказкой `--subnet`. Пропуск при `--no-service`.
- [x] **A5. Запасной источник IP** (п. 10): `api.ipify.org`, затем `ifconfig.me/ip`, `icanhazip.com`; ответ валидировать как IPv4.
- [x] **A6. Очистка при неудачной установке** (п. 6). `trap` на EXIT до первого успешного старта сервиса: удалить `awg0.conf` и файлы, созданные этим запуском; после успешного старта trap снимается. С `--no-service` — то же до конца записи файлов.
- [x] **A7. Ротация бэкапов** (п. 11): после создания `*.bak-*` оставлять 5 последних каждого вида.

## Фаза B — только после прогона на ВМ

- [x] **B1. MSS clamping** (п. 2): в `awg_forward` `oifname "awg0" tcp flags syn tcp option maxseg size set rt mtu` (и для `iifname`); миграция `nat-up.nft` в `update.sh`. ВМ: загрузка крупного файла через туннель при заблокированном ICMP frag-needed до и после.
- [x] **B2. Watchdog и `failed`** (п. 3): при `failed` — `systemctl reset-failed` + `start` не чаще раза в 5 минут (штамп в `/run`), явная строка в журнале. ВМ: сломанный бинарник → повторы с паузой, восстановление после починки.
- [x] **B3. ufw после flush** (п. 8): если ufw активен и его цепочки пропали — `ufw reload`. ВМ: `systemctl restart nftables` → туннель и ufw восстановлены.

## Фаза C — решения и удобство

- [x] **C1. Pinning апстрима** (п. 4): `upstream.lock` с проверенными коммитами; install/update собирают закреплённые; `update.sh --check` сообщает о новых коммитах апстрима отдельно.
- [x] **C2. Общая библиотека** (п. 9): `lib/common.sh` → `/usr/local/lib/awg-vps-kit/`; учесть запуск через `curl | bash` и установленный отдельно `awg-client`.
- [ ] **C3. Удобство:** `awg-client list` с handshake/трафиком (`awg show dump`), настраиваемый DNS клиентов, `rename`/`export`.

## Проверка

Каждая задача: сначала тест, воспроизводящий проблему, затем исправление; `bash -n` и shellcheck локально, контейнерные тесты — в CI. Фаза B не сливается без записи результатов ВМ в `docs/testing/reliability-vm.md`.
